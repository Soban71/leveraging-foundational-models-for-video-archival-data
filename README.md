Video Archive RAG — Setup & Run Guide
A multimodal (visual + speech/subtitle) Retrieval-Augmented Generation system for
searching a video archive. Clips are embedded with OpenCLIP (visual frames + text/
transcripts), stored in ChromaDB, retrieved with a weighted visual+text search, and
answered with a locally running Llama 3.1 8B model via Ollama. A FastAPI backend
serves the search/answer endpoints and video files to a React frontend.
Follow the steps in order — each script depends on the folder/output created
by the one before it.

2. Project folder structure
Create the project like this. Folders marked (auto-created) are generated by
the scripts themselves — you don't need to make them by hand, just don't delete
them mid-pipeline.

project/
├── videos/                  # 👉 YOU add your raw source videos here (.mp4/.mov/.avi/.mkv)
├── clips/                   # (auto-created by split_videos.py)
├── clips_web/                # (auto-created by convert_clips_for_web.py)
├── chroma_store/              # (auto-created — the vector database)
├── transcripts/               # (auto-created by create_textembeddings.py)
├── subtitles/                # optional — put .srt/.vtt files here if you have them
│
├── clip_descriptions.json     # 👉 YOU provide this (manual visual descriptions per clip)
├── evaluation_dataset.json    # 👉 YOU provide this (ground-truth queries, only needed to run evaluation.py)
│
├── split_videos.py
├── create_embeddings.py
├── create_textembeddings.py
├── vector_database.py
├── search.py
├── evaluation.py
├── frame_similarity_experiment.py
├── convert_clips_for_web.py
├── rag.py
├── api.py
├── requirements.txt
│
└── frontend/                  # your React app (not part of this backend repo)


clip_descriptions.json must be a list of objects shaped like this (one per clip):

{
  "clip_id": "MyVideo_clip_1",
  "video_id": "MyVideo",
  "clip_file": "MyVideo_clip_1.mp4",
  "clip_path": "clips\\MyVideo_clip_1.mp4",
  "start_time_seconds": 0.0,
  "end_time_seconds": 30.0,
  "description": "a short manual description of what's visible in the clip"
}


This is only used by rag.py to give the LLM grounded visual context — without it,
answers will just say "No visual description available."

python -m venv venv
venv\Scripts\activate          # Windows

4. Run the pipeline — IN THIS ORDER
Every step below must be run from the project root, and each one must finish
successfully before the next will work.

Step 1 — Split raw videos into 30-second clips

python split_videos.py


Reads everything in videos/, writes 30-second clips into clips/
(e.g. MyVideo_clip_1.mp4, MyVideo_clip_2.mp4, …).

Step 2 — Create visual (frame) embeddings

python create_embeddings.py


Extracts a frame every 2 seconds from each clip in clips/, embeds each frame
with OpenCLIP (ViT-B-32, laion2b_s34b_b79k), and stores them in ChromaDB
at chroma_store/ under the collection video_frame_embeddings.

Step 3 — Create text (transcript) embeddings

python create_textembeddings.py


For each clip, in priority order it tries: an existing file in transcripts/,
a sidecar .srt/.vtt in clips//subtitles//videos/, an embedded subtitle
stream in the source video, and finally Whisper speech-to-text on the matching
30-second audio window from videos/. Saves each transcript to transcripts/
and embeds it into ChromaDB under video_text_embeddings.

Needs the original files still in videos/ (it re-reads audio/subtitles from there).


Step 4 — Sanity-check the vector database (optional)

python vector_database.py


Just confirms both collections load correctly and prints how many embeddings
were found.

Step 5 — Test retrieval

python search.py


Interactive prompt — type a query and see the top 5 retrieved clips (visual +
text combined, 80/20 weighted) with their scores. Confirm this works and
returns sensible clips before moving on.

Step 6 — (Optional) Evaluate retrieval quality

python evaluation.py


Needs evaluation_dataset.json at the project root. Lets you evaluate a single
query ID (e.g. Q01), or type all to get averaged Precision/Recall/F1/Hit@5
across Visual-only, Text-only, and Visual+Text retrieval.

Step 7 — (Optional) Frame-similarity experiment

python frame_similarity_experiment.py


A separate experiment that scores clips by their single best-matching frame
(rather than the top-3-average method in search.py) and writes results to a
CSV. Not required for the app to run.

Step 8 — Convert clips to browser-friendly MP4

python convert_clips_for_web.py


The clips from Step 1 (written by OpenCV) usually aren't in a codec browsers can
play. This re-encodes everything from clips/ into H.264/AAC with faststart
and writes the results to clips_web/. api.py serves video from clips_web/,
so this step is required before the frontend can actually play any clips.


5. Install & start Ollama (the answer generator)

ollama pull llama3.1:8b
ollama serve


Leave ollama serve running in its own terminal — rag.py/api.py call it at
http://localhost:11434/api/generate. An 8B model on CPU can take a couple of
minutes per answer; that's expected.
You can test the whole RAG pipeline from the terminal before touching the API:

python rag.py




6. Run the backend API

uvicorn api:app --reload


This will fail immediately if clips_web/ doesn't exist yet (Step 8), so make
sure that step ran first. On startup it loads both ChromaDB collections and the
OpenCLIP model once, then exposes:


POST /api/retrieve — fast clip retrieval only

POST /api/generate — full RAG answer via Ollama (slower)

GET /api/clip/{clip_file} — streams a clip from clips_web/


GET /api/health — health check

Default CORS allows http://localhost:5173 and http://localhost:3000.


7. Run the frontend

cd frontend
npm install
npm run dev


Then open the printed local URL (typically http://localhost:5173) in your
browser. It talks to the backend from Step 6.


Quick-reference: full run order

1. Put source videos in videos/
2. python split_videos.py
3. python create_embeddings.py
4. python create_textembeddings.py
5. python search.py            # confirm retrieval works
6. python evaluation.py        # optional
7. python convert_clips_for_web.py
8. ollama pull llama3.1:8b && ollama serve
9. uvicorn api:app --reload
10. cd frontend && npm install && npm run dev



Troubleshooting


"ffmpeg was not found" — install FFmpeg and make sure it's on PATH.

RuntimeError: The 'clips' folder was not found beside api.py — you skipped
Step 8; run convert_clips_for_web.py so clips_web/ exists.

Ollama timeouts / no answer — make sure ollama serve is running and
llama3.1:8b has been pulled; first response after starting Ollama is slower.

Empty/odd search results — re-run Steps 3 and 4 after confirming new clips
landed in clips/, since the collections are rebuilt (old ones deleted) each run.

Whisper import error — only needed if a clip has no subtitles at all;
install with pip install -U openai-whisper.
